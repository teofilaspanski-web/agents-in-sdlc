GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行しながら自律的に作業します。作業は開発者のマシン上でリアルタイムに進むため、VS Code の Copilot Chat にはツール呼び出しやファイル編集の状況が表示されます。差分をインラインで確認し、個々の変更を承認または取り消し、エディターを離れずに追加のプロンプトで会話を調整したり作業範囲を広げたりできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッションの途中でエージェントにライトモードの切り替え機能も依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替え機能も追加します。新しい会話を最初から始めるのではなく、現在のセッションを調整して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集内容は、差分と **Keep** / **Undo** のコントロールとともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み込みや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可を求められると、エージェントは一時停止し、**Allow** プロンプトを表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライトモードの追加を依頼する

ハイコントラストモードができたので、同じ会話でライトモードの切り替え機能も追加します。同じチャットセッションを続けると、エージェントは以前の作業のコンテキストを保持します。変更したコンポーネント、採用したスタイル、設定したローカルストレージのパターンなどが含まれます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは以前の変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードの場合と同様に、新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. たとえば、エージェントが好みと異なる方法で切り替え UI を再構成しようとした場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送信します。

> [!TIP]
> 作業中のセッションを調整する方が、最初からやり直すより短時間で済みます。追加プロンプトを使うと、変更を依頼できます (「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」)。また、方向を修正できます (「3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合してください」)。作業範囲を広げることもできます (「両方の切り替えにキーボードショートカットも追加してください」)。

## 作業ファイルを確認する

作業をコミットする前に、エージェントが変更したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターンが反映されていることを確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存などが対象です。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中のセッションを監視し、調整しました。ファイル編集が反映されるたびに確認し、変更を承認または取り消し、コンテキストを保ったまま追加プロンプトで作業を広げました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- セッションの途中で追加プロンプトを送り、方向を調整しました。
