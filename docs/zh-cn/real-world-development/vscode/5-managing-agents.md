启用 GitHub Copilot 代理模式后，它会自主探索代码库、提出更改、编辑文件并运行命令。由于这些工作实时发生在你的计算机上，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。你可以内联审阅每个差异、接受或拒绝单项更改，并通过后续提示引导对话，在不离开编辑器的情况下完善或扩展工作。

本练习将完成以下目标：

- 实时监控无障碍代理的工作。
- 审阅并接受建议的文件编辑。
- 在会话进行中引导代理，在高对比度模式之外添加浅色模式切换开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义代理正在实现高对比度模式。工作进行期间，设计团队提出了额外需求：为觉得默认主题太暗的用户添加浅色模式切换开关。无需从头开始新对话，你可以引导当前会话扩展工作。

## 监控 Copilot 进度

Copilot Chat 视图会显示代理执行的每个步骤，包括探索的文件、运行的命令和提出的编辑。每次文件编辑都会在聊天中内联显示差异和 **Keep** / **Undo** 控件。

1. 返回练习 4 使用的 Copilot Chat 视图。
2. 代理工作期间，滚动聊天内容，查看每次工具调用。你会看到文件读取、文件编辑以及需要运行的终端命令。
3. 代理提出文件编辑时，差异会内联显示：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 撤销更改，让代理再次尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看本次会话中代理修改的全部文件。

> [!NOTE]
> 如果工具调用请求权限（例如运行终端命令），代理会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待代理完成高对比度模式。完成后应会看到总结更改内容的消息。

## 引导代理添加浅色模式

高对比度模式已经就绪，现在扩展同一对话，添加浅色模式切换开关。由于继续使用同一聊天会话，代理会保留先前工作的上下文，包括涉及的组件、所用样式方法和本地存储模式。

1. 在 Copilot Chat 用户界面（UI）的输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在在高对比度切换开关旁添加浅色模式切换开关。浅色模式应采用相同模式，通过本地存储持久保存，并能从 UI 的同一区域访问。用户应能分别启用高对比度和浅色模式。
    ```

2. 代理会接着之前的工作，探索已完成的更改并提出浅色模式相关修改。
3. 与高对比度模式一样，逐项审阅新编辑。使用 **Keep** 或 **Undo** 处理每个差异。
4. 如果代理的方向不符合预期（例如尝试以你不喜欢的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清后的后续消息。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以使用后续提示要求调整（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个开关，将浅色模式集成到现有设置面板”）或扩展范围（“为两个开关添加键盘快捷键”）。

## 审阅工作集

提交工作前，快速检查代理修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审阅更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个已更改文件并查看差异。确认实现符合自定义代理提出的无障碍模式，包括无障碍富互联网应用（ARIA）属性、键盘导航、语义化 HTML 和本地存储。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课将发布这些更改。

## 总结和后续步骤

你使用 Copilot Chat 代理模式监控并引导了正在进行的会话：逐项审阅文件编辑、接受或拒绝更改，并通过后续提示扩展工作，同时保留现有上下文。

本课中，你了解了：

- 实时监控代理工作。
- 接受或拒绝单项文件编辑。
- 使用后续提示引导正在进行的会话。
